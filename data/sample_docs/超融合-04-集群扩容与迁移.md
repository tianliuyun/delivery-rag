## 超融合集群在线扩容与虚拟机迁移指南

本文适用于主流超融合平台（如 VMware vSAN、Nutanix AHV、等）的在线扩容与迁移操作。操作前请确认集群健康状态为“正常”，且无未决告警。

### 一、新增节点步骤

#### 1.1 前置检查
- 新节点硬件型号、固件版本与现网节点一致。
- 管理网口、存储网口、迁移网口已按规划连线。
- 新节点已安装与集群相同版本的系统及超融合组件。
- 集群当前存储利用率 ≤ 70%，否则先清理或扩容再添加节点。

#### 1.2 加入集群
1. 登录超融合管理平台，进入 **集群 > 节点 > 添加节点**。
2. 输入新节点管理 IP、root 密码，点击“发现节点”。
3. 选择“在线加入”，平台自动分发集群配置。
4. 等待节点状态变为“已加入”，通常耗时 5–15 分钟。
5. 验证：`cluster status` 或平台界面显示节点数为 N+1，且各节点心跳正常。

#### 1.3 网络与存储配置
- 为存储网口绑定双万兆链路，MTU 建议 9000。
- 若使用 vSAN，确认新节点磁盘组已自动创建或手动添加。
- 检查端口连通性：`nc -zv <节点IP> 111`（NFS）、`nc -zv <节点IP> 2049`、`nc -zv <节点IP> 3260`（iSCSI）。

### 二、存储池扩容

#### 2.1 扩容前提
- 新节点磁盘已加入集群存储池。
- 集群无重建任务，`vsan.resync` 或等效指标低于 20%。

#### 2.2 操作步骤
1. 进入 **存储 > 存储池 > 扩容**。
2. 勾选新节点上的可用磁盘或磁盘组。
3. 选择扩容策略：**均衡分布**（推荐）或 **追加容量**。
4. 设置数据重建限速：建议 100–200 MB/s，避免影响业务。
5. 执行扩容，观察任务进度。
6. 完成后验证：
   - 总容量 = 原容量 + 新节点有效容量。
   - 数据分布均匀，各节点利用率偏差 ≤ 5%。

#### 2.3 阈值告警
- 扩容后若单节点利用率 > 80%，需触发再平衡。
- 重建期间 IO 延迟 > 20 ms 时，自动降速至 50 MB/s。

### 三、虚拟机在线迁移前提条件

| 项目 | 要求 |
|------|------|
| 集群状态 | 健康，无隔离节点 |
| 源/目标主机 | 同一集群，CPU 厂商与代次兼容 |
| 网络 | 迁移网口 ≥ 10 GbE，延迟 < 1 ms |
| 存储 | 共享存储或超融合分布式存储 |
| 虚拟机 | 无 CD-ROM 挂载 ISO、无直通设备 |
| 端口 | 迁移端口 8000（VMware vMotion）、16509（libvirt）、29876（Nutanix） |
| 权限 | 管理员或迁移专用角色 |

#### 3.1 迁移前校验清单
- [ ] 虚拟机无快照或快照已合并。
- [ ] 目标节点资源充足：CPU ≤ 70%，内存 ≤ 80%。
- [ ] 迁移网络已启用，`vmkping <目标IP>` 通。
- [ ] 虚拟机磁盘为厚置备或精简置备且存储兼容。
- [ ] 关闭虚拟机内不必要的 USB 设备。

#### 3.2 迁移操作
1. 右键虚拟机 > **迁移** > **更改主机**。
2. 选择目标节点，选择迁移优先级：**高**（在线迁移）。
3. 点击“开始”，观察任务进度。
4. 迁移完成后，虚拟机状态保持“运行中”。

#### 3.3 迁移后校验清单
- [ ] 虚拟机 IP 未变，业务端口可访问。
- [ ] 无丢包：`ping -c 100 <虚拟机IP>` 丢包率 0%。
- [ ] 存储路径已切换至目标节点。
- [ ] 事件日志无“迁移失败”或“超时”记录。
- [ ] 源节点资源释放，CPU/内存回落至正常水平。

### 四、回滚与故障处理

- 迁移失败：检查端口 8000/16509 是否被防火墙拦截。
- 扩容失败：回滚磁盘组，重新加入。
- 重建卡住：`esxcli vsan cluster get` 查看状态，必要时重启管理服务。

操作完成后，记录变更时间、节点 IP、扩容前后容量、迁移虚拟机列表，归档至交付文档。
