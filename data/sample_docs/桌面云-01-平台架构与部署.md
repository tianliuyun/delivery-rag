## 桌面云平台整体架构与部署指南

## 1. 架构概述

桌面云平台采用分层解耦架构，核心组件包括：连接代理（Connection Broker）、虚拟桌面池（Desktop Pool）、会话网关（Session Gateway）、认证服务（Auth Service）、许可证服务（License Service）。各组件通过标准 TCP/UDP 端口通信，支持单机部署与集群部署两种模式。

## 2. 核心组件与通信端口

### 2.1 组件功能

| 组件 | 功能 |
|------|------|
| 连接代理 | 会话调度、桌面分配、状态监控 |
| 虚拟桌面池 | 托管虚拟机或容器化桌面实例 |
| 会话网关 | 外部接入、协议代理、加密隧道 |
| 认证服务 | 用户身份验证、AD/LDAP 集成、MFA |
| 许可证服务 | 授权校验、并发用户计数、到期管理 |

### 2.2 组件间通信端口

| 源组件 | 目标组件 | 协议 | 端口 | 用途 |
|--------|----------|------|------|------|
| 连接代理 | 认证服务 | HTTPS | 443 | 用户认证请求 |
| 连接代理 | 虚拟桌面池 | TCP | 5500 | 桌面状态上报 |
| 连接代理 | 许可证服务 | TCP | 8443 | 授权校验 |
| 会话网关 | 连接代理 | TLS | 9443 | 会话建立 |
| 会话网关 | 虚拟桌面池 | TCP | 3389/5900 | RDP/VNC 代理 |
| 认证服务 | AD/LDAP | LDAP/S | 389/636 | 目录查询 |
| 许可证服务 | 连接代理 | TCP | 8443 | 心跳与计数 |
| 客户端 | 会话网关 | HTTPS/WSS | 443 | 接入 |

> 内部组件间建议启用 mTLS，证书端口统一为 9443。

## 3. 部署步骤

### 3.1 单台部署（PoC/小型环境）

1. **准备主机**：OS 为 Ubuntu 22.04 LTS，8 vCPU / 32 GB RAM / 500 GB SSD。
2. **安装依赖**：
   ```bash
   sudo apt update && sudo apt install -y docker.io docker-compose nginx
   ```
3. **部署认证服务**：
   ```bash
   docker run -d --name auth -p 443:443 -v /etc/auth:/config auth-service:2.1
   ```
4. **部署许可证服务**：
   ```bash
   docker run -d --name license -p 8443:8443 license-service:1.8
   ```
5. **部署连接代理**：
   ```bash
   docker run -d --name broker -p 5500:5500 -p 9443:9443 broker:3.0
   ```
6. **部署会话网关**：
   ```bash
   docker run -d --name gateway -p 443:443 -p 3389:3389 gateway:2.5
   ```
7. **部署虚拟桌面池**：使用 KVM 创建 5 台 Ubuntu 桌面模板，注册至连接代理：
   ```bash
   pool-cli register --broker 127.0.0.1:5500 --template ubuntu-desktop
   ```
8. **验证**：访问 `https://<host>`，使用 AD 账号登录，确认桌面可启动。

### 3.2 集群部署（生产环境）

1. **节点规划**：至少 3 台连接代理、2 台会话网关、2 台认证服务、2 台许可证服务。
2. **配置共享存储**：NFS 挂载至 `/shared`，用于桌面模板与配置同步。
3. **部署认证服务集群**：
   ```bash
   docker swarm init
   docker service create --name auth --replicas 2 -p 443:443 auth-service:2.1
   ```
4. **部署许可证服务集群**：
   ```bash
   docker service create --name license --replicas 2 -p 8443:8443 license-service:1.8
   ```
5. **部署连接代理集群**：
   ```bash
   docker service create --name broker --replicas 3 -p 5500:5500 -p 9443:9443 broker:3.0
   ```
6. **部署会话网关集群**：前置 L4 负载均衡（HAProxy），后端 2 个网关实例：
   ```
   frontend gateway
     bind *:443
     default_backend gw_nodes
   backend gw_nodes
     server gw1 10.0.0.11:443 check
     server gw2 10.0.0.12:443 check
   ```
7. **加入虚拟桌面池**：每台宿主机运行 `pool-agent`，向连接代理集群注册。
8. **验证高可用**：关闭任一连接代理，会话应在 30 秒内切换至其他节点。

## 4. 容量规划建议

| 资源 | 单用户阈值 | 100 用户 | 500 用户 |
|------|------------|----------|----------|
| vCPU | 2 | 200 | 1000 |
| RAM | 4 GB | 400 GB | 2 TB |
| 存储 | 40 GB | 4 TB | 20 TB |
| 连接代理 | 1 节点/200 用户 | 1 | 3 |
| 会话网关 | 1 节点/500 并发 | 1 | 2 |
| 认证服务 | 1 节点/1000 用户 | 1 | 2 |
| 许可证服务 | 1 节点/2000 用户 | 1 | 1 |

**建议**：
- 连接代理 CPU 使用率持续 >70% 时横向扩展。
- 会话网关带宽按每并发用户 2 Mbps 预留。
- 许可证服务需预留 10% 冗余授权数。
- 虚拟桌面池超分比不超过 1:8（vCPU 与物理核心比）。
