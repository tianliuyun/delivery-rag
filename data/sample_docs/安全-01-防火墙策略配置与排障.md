## 防火墙策略配置与排障手册

## 一、策略优先级规则

主流防火墙（如华为USG、H3C SecPath、Cisco ASA、Palo Alto）均采用**自上而下、首次匹配即生效**的规则模型。策略匹配遵循以下优先级：

1. **安全策略 > 缺省策略**：显式配置的规则优先于 default deny/allow。
2. **具体性优先**：五元组越精确（源/目的IP、端口、协议）的规则应置于宽泛规则之上。
3. **NAT策略与安全策略分离**：先匹配NAT（源NAT/目的NAT），再做安全过滤，顺序错误会导致策略不生效。
4. **区域间策略独立**：`trust→untrust` 与 `untrust→trust` 需分别配置，方向不可复用。
5. **长连接/会话保持策略**：需显式放行双向流量，或启用 `session aging-time` 配合。

**配置建议**：按“管理面 → 业务面 → 兜底拒绝”三段式编排，每条策略添加 description 标注业务系统与工单号。

## 二、端口放行规划

### 2.1 规划原则

- 最小化放行：仅开放业务必需端口，禁止 `any/any`。
- 源目精确：生产环境禁止使用 `0.0.0.0/0` 作为源地址。
- 双向确认：TCP需确认握手方向，UDP需确认会话保持时间。

## 三、策略不生效排查

### 3.1 策略优先级错误

**现象**：流量被拒绝，但已配置放行策略。

**排查步骤**：
1. 执行 `display security-policy rule all`（华为）或 `show running-config access-list`（Cisco）。
2. 检查是否存在更靠前的 deny 规则命中。
3. 使用 `display firewall session table source x.x.x.x destination y.y.y.y` 查看会话匹配的策略ID。
4. 调整规则顺序：`security-policy` 视图下使用 `move rule` 或重新编号。

### 3.2 规则顺序冲突

**现象**：新增策略后原业务中断。

**排查步骤**：
1. 对比变更前后 `rule id` 顺序，确认新规则未覆盖旧规则。
2. 检查是否存在**子网掩码包含关系**：如 `10.0.0.0/8` 会覆盖 `10.1.1.0/24`。
3. 检查端口范围重叠：`any` 端口规则会拦截后续精确端口规则。
4. 使用 `display security-policy statistics` 查看各规则命中计数，定位实际生效规则。

### 3.3 会话老化

**现象**：策略已放行，但长连接间歇性中断。

**排查步骤**：
1. 查看会话老化时间：`display firewall session aging-time`。
2. 常见默认值：TCP 3600s、UDP 120s、ICMP 20s。
3. 对长连接业务（如数据库、视频流）调整：
   ```
   firewall session aging-time tcp 86400
   firewall session aging-time udp 600
   ```
4. 启用会话保持：`long-link` 或 `session persistent`。
5. 检查是否存在**会话表溢出**：`display firewall session table verbose | include count`，超过规格需扩容或优化。

### 3.4 通用排障命令

```bash
# 抓包确认流量是否到达防火墙
capture-packet interface GigabitEthernet0/0/1 destination 10.1.1.100

# 查看策略命中
display security-policy rule name <rule-name>

# 实时会话监控
display firewall session table verbose | include 10.1.1.100

# 调试丢包
debugging security-policy all
terminal monitor
```

**排障顺序**：物理链路 → 路由 → NAT → 安全策略 → 会话表 → 应用层。
