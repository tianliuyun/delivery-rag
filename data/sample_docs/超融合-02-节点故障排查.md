## 超融合节点故障排查手册：节点离线/宕机/掉线的处理流程

### 一、故障分级与初步判断

节点“离线/宕机/掉线”通常表现为：
- 管理界面（如 Prism、vCenter、FusionCompute）中节点状态为 **Disconnected / Offline / 未知**
- 集群内其他节点无法通过心跳网络（通常为 10G/25G 内网）访问该节点
- 存储池（如 vSAN、Ceph、Distributed Storage）显示该节点 **Degraded / Absent**

**处理原则：先物理，后网络，再集群，最后数据。**

### 二、第一步：物理机状态检查（0–5 分钟）

1. **带外管理口（IPMI/iDRAC/iLO）登录**
   - 默认端口：`443`（HTTPS）、`623`（IPMI）
   - 检查项：电源状态、风扇、温度、内存/CPU 告警、最近 SEL 日志
2. **若无法带外访问**：现场检查电源指示灯、网口 Link 灯、KVM 是否卡在 BIOS/OS 启动阶段
3. **强制重启前**：记录 `last reset reason`，避免直接断电导致存储元数据损坏
4. **恢复供电后**：进入 BIOS/UEFI，确认启动项为本地磁盘/RAID 卷，关闭 PXE 优先

### 三、第二步：网卡与固件检查（5–15 分钟）

1. **登录节点 OS（若可 SSH）**
   ```bash
   ip -br link show
   ethtool <nic_name> | grep -E "Speed|Link detected"
   ```
   - 要求：管理网 ≥1Gbps，存储网 ≥10Gbps，Link detected: yes
2. **检查 bonding/team 状态**
   ```bash
   cat /proc/net/bonding/bond0
   ```
   - 确认 `MII Status: up`，且至少一个 slave 为 up
3. **固件版本核对**
   - NIC 固件：`ethtool -i <nic>` 对比厂商推荐版本
   - BIOS/RAID/HBA 固件：通过带外或 `dmidecode -t bios` 查看
   - **阈值**：固件版本差异 ≥2 个大版本时，必须在维护窗口升级
4. **常见故障**：光模块收光功率低于 `-10dBm`、交换机端口 err-disable、MTU 不一致（存储网建议 `9000`）

### 四、第三步：存储网络与集群心跳检查（15–30 分钟）

1. **存储网络连通性**
   ```bash
   ping -M do -s 8972 <peer_storage_ip>   # 测试 9000 MTU
   ping <peer_storage_ip>
   ```
   - 丢包率 >0.1% 或 RTT >2ms 视为异常
2. **集群心跳端口**
   - vSAN：`2233`（TCP/UDP）
   - Ceph：`6789`（mon）、`6800-7300`（osd）
   - 检查防火墙/ACL：
     ```bash
     iptables -L -n | grep -E "2233|6789|6800"
     ```
3. **集群状态查询**
   - vSAN：`esxcli vsan cluster get`，确认节点 `Member` 状态
   - Ceph：`ceph -s`，关注 `mon` quorum 与 `osd` down 数量
   - 若 quorum 丢失，**禁止**强制拉起节点，先恢复网络

### 五、节点恢复后的数据重建与自愈检查

1. **重新加入集群**
   - vSAN：`esxcli vsan cluster join -u <uuid>`
   - Ceph：确认 `ceph osd tree` 中该 OSD 为 `up` 且 `in`
2. **触发数据重建**
   - vSAN：自动重建，检查 `esxcli vsan debug object list | grep -i "resync"`
   - Ceph：`ceph osd pool set <pool> min_size 1`（临时），重建完成后恢复为 `2`
3. **重建速率与阈值**
   - 建议限制重建带宽：vSAN `esxcli vsan storage resync throttle set -t 100`（MB/s）
   - Ceph：`ceph tell osd.* injectargs '--osd_max_backfills=2'`
   - 观察 `recovery` 速率，正常 ≥50MB/s/节点
4. **自愈完成检查清单**
   - [ ] 集群状态 `HEALTH_OK` 或 vSAN `Healthy`
   - [ ] 所有 OSD/磁盘组 `up/in`
   - [ ] 数据一致性校验：`ceph pg scrub <pgid>` 或 vSAN `Object Repair`
   - [ ] 心跳延迟 <5ms，存储网无丢包
   - [ ] 带外告警清零，固件版本一致

### 六、常见误操作与规避

- **禁止**在存储网未通时强制格式化磁盘或重建 RAID
- **禁止**同时重启两个及以上节点（除非确认副本数 ≥2 且健康）
- **禁止**在重建未完成时进行固件批量升级

### 七、升级路径

若 30 分钟内无法恢复物理机，立即：
1. 将该节点标记为 `Maintenance Mode`（vSAN）或 `ceph osd out`
2. 确认剩余节点副本充足
3. 走硬件更换流程，新节点按“裸机→固件→网络→加入集群”顺序交付
