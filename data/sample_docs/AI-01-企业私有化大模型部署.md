## 企业私有化大模型部署指南

### 1. 模型选型：7B 与 14B 的适用边界

| 参数量 | 典型模型 | 最低显存（FP16） | 推荐场景 |
|--------|----------|------------------|----------|
| 7B | Qwen2.5-7B-Instruct / Llama-3.1-8B | 16GB | 高并发问答、摘要、分类 |
| 14B | Qwen2.5-14B-Instruct / Yi-1.5-14B | 32GB | 复杂推理、代码生成、RAG |

**选型原则**：7B 用于 TPS > 50 的在线服务；14B 用于质量优先、并发 < 20 的场景。若显存不足，优先降量化而非降参数量。

### 2. 推理框架：vLLM 与 PagedAttention

vLLM 通过 PagedAttention 将 KV Cache 分页管理，显存利用率可达 90% 以上。部署命令示例（7B INT4，单卡 A10 24GB）：

```bash
python -m vllm.entrypoints.openai.api_server \
  --model /models/Qwen2.5-7B-Instruct-AWQ \
  --quantization awq \
  --dtype float16 \
  --gpu-memory-utilization 0.90 \
  --max-model-len 8192 \
  --max-num-seqs 64 \
  --port 8000 \
  --host 0.0.0.0
```

**关键参数阈值**：
- `--gpu-memory-utilization`：0.85~0.92，超过 0.95 易 OOM
- `--max-model-len`：7B 建议 ≤ 8192；14B 建议 ≤ 4096
- `--max-num-seqs`：7B 单卡 64；14B 单卡 32

验证服务：

```bash
curl http://127.0.0.1:8000/v1/models
```

### 3. 量化方案：INT8 与 INT4

| 方案 | 精度损失 | 显存节省 | 推荐工具 |
|------|----------|----------|----------|
| INT8 | < 1% | 50% | bitsandbytes / GPTQ |
| INT4 | 2~5% | 75% | AWQ / GPTQ |

**交付建议**：
- 7B 优先 AWQ INT4，显存占用约 5GB，可单卡部署多实例
- 14B 优先 INT8，显存约 16GB，质量更稳
- 量化后必须跑 50 条业务样本回归，BLEU 或人工评分下降 > 5% 则回退

生成 AWQ 模型：

```bash
pip install autoawq
python -c "
from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer
model = AutoAWQForCausalLM.from_pretrained('/models/Qwen2.5-7B-Instruct')
tok = AutoTokenizer.from_pretrained('/models/Qwen2.5-7B-Instruct')
model.quantize(tok, quant_config={'w_bit':4,'q_group_size':128,'zero_point':True})
model.save_quantized('/models/Qwen2.5-7B-Instruct-AWQ')
"
```

### 4. GPU 资源规划

**单卡显存公式**：`模型权重 + KV Cache + 激活 ≈ 参数量×量化字节 + 并发×序列长×2×层数×隐藏维`

**推荐配置**：
- 7B INT4：A10 24GB × 1，支持 64 并发，8K 上下文
- 14B INT8：A100 40GB × 1 或 L20 48GB × 1，支持 32 并发
- 多卡：使用 `--tensor-parallel-size 2`，仅限同型号 NVLink 互联

**监控命令**：

```bash
nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu --format=csv -l 5
```

显存持续 > 92% 时，降低 `--max-num-seqs` 或 `--max-model-len`。

### 5. API 网关与权限控制

**架构**：vLLM (8000) → Nginx (443) → 业务系统

Nginx 配置片段：

```nginx
location /v1/ {
    proxy_pass http://127.0.0.1:8000/v1/;
    proxy_set_header Authorization $http_authorization;
    proxy_read_timeout 300s;
    limit_req zone=llm burst=20 nodelay;
}
```

**权限控制**：
1. 在网关层校验 `Authorization: Bearer <API_KEY>`
2. 按租户分配 Key，记录调用量至 Redis（端口 6379）
3. 限流阈值：单 Key 默认 10 QPS，超限返回 429
4. 审计日志落盘 `/var/log/llm/access.log`，保留 90 天

**Key 生成示例**：

```bash
openssl rand -hex 32
```

### 6. 交付检查清单

1. 模型权重 MD5 校验通过
2. vLLM 服务 `curl /v1/models` 返回 200
3. 压测 100 并发，P99 延迟 < 3s
4. 量化回归评分下降 ≤ 5%
5. 网关限流与鉴权生效
6. 监控告警接入 Prometheus (9090) + Grafana (3000)
