## 业务割接与变更管理方案

### 1. 割接前准备

#### 1.1 回退方案

割接失败时须在 **30 分钟**内恢复原生产环境。回退触发条件：

- 核心业务接口错误率 > 5%，持续 5 分钟
- 数据库主从延迟 > 30s
- 关键交易 TPS 下降超过基线 40%

回退方式：

- 应用层：DNS 权重切回原集群（TTL 预置为 60s）
- 数据层：停止新集群写入，反向同步增量数据后切回原库
- 配置层：保留原 Nginx upstream 配置文件 `/etc/nginx/conf.d/app_bak.conf`

#### 1.2 备份

| 对象 | 方式 | 命令/工具 | 校验 |
|------|------|-----------|------|
| MySQL | 全量+binlog | `mysqldump --single-transaction -uroot -p db > db_$(date +%F).sql` | `md5sum` 比对 |
| Redis | RDB | `redis-cli -h 10.0.0.11 -p 6379 BGSAVE` | 检查 `rdb_last_bgsave_status:ok` |
| 应用配置 | Git tag | `git tag cutover-20240601 && git push --tags` | tag 存在性 |
| 对象存储 | 跨区复制 | `aws s3 sync s3://prod-bucket s3://backup-bucket` | 对象数量一致 |

#### 1.3 窗口规划

- 割接窗口：**周六 02:00–05:00**（业务低峰）
- 冻结期：割接前 24h 停止非必要变更
- 观察期：割接后 72h 保持双人值守
- 通知：提前 3 个工作日邮件+IM 通知业务方

### 2. 割接步骤

1. **T-30min**：确认备份完成，记录基线指标（TPS、RT、错误率）
2. **T-10min**：在负载均衡器摘除新集群节点，仅保留原集群
3. **T0**：停止原集群写入，执行最终增量同步
   ```bash
   pt-heartbeat --update --database heartbeat --host 10.0.0.10
   ```
4. **T+5min**：启动新集群应用，检查端口监听
   ```bash
   ss -lntp | grep -E '8080|8443|3306|6379'
   ```
5. **T+10min**：DNS 权重逐步切换：10% → 50% → 100%，每步间隔 5 分钟
6. **T+30min**：执行验证清单（见第 3 节）
7. **T+60min**：确认无异常后，原集群转为只读备用

### 3. 业务验证清单

#### 3.1 连通性

- `telnet 10.0.1.20 8080` 返回 Connected
- `curl -I https://api.example.com/health` 返回 `HTTP/2 200`
- 数据库连接：`mysql -h 10.0.1.30 -P 3306 -u app -p -e "SELECT 1"`
- Redis：`redis-cli -h 10.0.1.40 -p 6379 ping` 返回 PONG
- 内部服务调用：`curl http://order-svc:9090/actuator/health` 返回 `{"status":"UP"}`

#### 3.2 性能

| 指标 | 阈值 | 采集命令 |
|------|------|----------|
| API P99 RT | < 500ms | `wrk -t4 -c100 -d60s https://api.example.com/v1/query` |
| TPS | ≥ 基线 90% | Prometheus `rate(http_requests_total[1m])` |
| CPU | < 70% | `top -bn1 | grep Cpu` |
| 内存 | < 80% | `free -m` |
| DB 慢查询 | < 5 条/分钟 | `SHOW GLOBAL STATUS LIKE 'Slow_queries'` |

#### 3.3 业务功能

- 用户登录：`POST /api/login` 返回 token
- 下单：`POST /api/order` 返回 orderId，DB 中可查到记录
- 支付回调：模拟 `POST /api/pay/notify` 返回 success
- 报表导出：`GET /api/report/export` 文件大小 > 0
- 消息队列：RabbitMQ 管理台 `15672` 确认队列无堆积

### 4. 失败回退流程

1. **判定**：任一验证项连续 2 次失败或触发 1.1 节条件
2. **决策**：割接指挥者 5 分钟内下达回退指令
3. **执行**：
   - 停止新集群流量：`nginx -s stop` 或摘除 VIP
   - DNS 切回原集群，权重 100%
   - 恢复原库写入：`SET GLOBAL read_only=OFF`
   - 反向同步新库增量数据（如已产生）
4. **验证**：重复第 3 节连通性与业务功能检查
5. **复盘**：24h 内输出回退报告，记录时间线、根因、改进项

回退完成后，须在变更管理系统（如 Jira/ServiceNow）中关闭割接单，并标记状态为 **Rolled Back**。
