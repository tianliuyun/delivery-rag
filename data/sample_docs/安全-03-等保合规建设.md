## 企业等级保护（等保）合规建设指南

### 一、安全区域划分

等保2.0要求按“一个中心、三重防护”原则划分安全区域。典型企业云环境应至少划分以下区域：

| 区域名称 | 功能定位 | 部署要求 |
|---------|---------|---------|
| 核心业务区 | 生产数据库、应用服务器 | 独立VLAN，禁止直接互联网暴露 |
| 管理区 | 堡垒机、监控、日志平台 | 与业务区逻辑隔离，仅运维终端可访问 |
| DMZ区 | 对外Web、API网关 | 双向访问控制，禁止直连核心区 |
| 办公区 | 员工终端 | 与生产区隔离，经防火墙策略放行 |
| 测试区 | 预发布、测试环境 | 独立子网，禁止使用生产数据 |

**操作步骤：**
1. 在VPC中为每个区域创建独立子网，例如核心业务区 `10.10.1.0/24`，管理区 `10.10.2.0/24`。
2. 配置安全组默认拒绝所有入站，按需放行。例如仅允许管理区 `10.10.2.0/24` 访问核心区22端口：
   ```bash
   iptables -A INPUT -s 10.10.2.0/24 -p tcp --dport 22 -j ACCEPT
   iptables -A INPUT -p tcp --dport 22 -j DROP
   ```
3. 跨区域流量必须经过防火墙或安全组策略，禁止扁平化网络。

### 二、访问控制策略

#### 2.1 身份认证
- 所有运维账户强制启用MFA，密码策略：长度≥12位，含大小写、数字、特殊字符，90天更换。
- 禁止root直接登录，使用普通用户+sudo提权。

#### 2.2 最小权限原则
- 数据库账户按应用授权，禁止 `GRANT ALL`。例如：
  ```sql
  GRANT SELECT, INSERT, UPDATE ON app_db.* TO 'app_user'@'10.10.1.%' IDENTIFIED BY '强密码';
  ```
- 云平台IAM策略绑定到角色，而非个人。例如仅允许特定角色操作ECS：
  ```json
  {
    "Effect": "Allow",
    "Action": ["ecs:StartInstance", "ecs:StopInstance"],
    "Resource": "acs:ecs:*:*:instance/i-xxxx"
  }
  ```

#### 2.3 网络访问控制
- 安全组规则优先级：拒绝所有，按需放行。常见端口：SSH 22、RDP 3389、MySQL 3306、HTTPS 443。
- 禁止0.0.0.0/0开放22/3389。若必须，限制源IP为公司出口IP。

### 三、日志审计要求

等保要求日志留存≥6个月，核心操作日志≥12个月。

**必须采集的日志源：**
- 操作系统：`/var/log/secure`、`/var/log/audit/audit.log`
- 数据库：慢查询、登录失败、DDL操作
- 网络设备：防火墙会话、拒绝记录
- 云平台：操作审计（ActionTrail/CloudTrail）

**配置示例（rsyslog转发）：**
```bash
# /etc/rsyslog.conf
*.* @@10.10.2.100:514
```
在日志服务器上启用 `auditd` 规则监控关键文件：
```bash
auditctl -w /etc/passwd -p wa -k passwd_change
auditctl -w /etc/ssh/sshd_config -p wa -k sshd_config
```

**审计平台要求：**
- 日志集中存储，禁止本地删除。
- 设置告警：5分钟内同一账户登录失败≥5次，触发告警。
- 每月导出审计报告，保留PDF+原始日志。

### 四、边界防护设备部署

#### 4.1 设备选型与部署位置
- **下一代防火墙（NGFW）**：部署在互联网出口与DMZ之间，开启IPS、AV、URL过滤。
- **WAF**：部署在Web服务器前，防护SQL注入、XSS。建议模式：先观察后拦截。
- **堡垒机**：部署在管理区，所有运维流量经堡垒机代理，录屏留存180天。
- **IDS/IPS**：镜像核心交换机流量，检测横向移动。

#### 4.2 关键配置参数
- 防火墙会话超时：TCP 3600秒，UDP 120秒。
- WAF CC防护：单IP 60秒内请求>100次则挑战验证。
- 堡垒机：禁止直连，强制双因子，命令黑名单包含 `rm -rf /`、`shutdown`。

**部署步骤：**
1. 互联网 → 防火墙（公网IP）→ WAF → DMZ负载均衡 → Web服务器。
2. 管理区 → 堡垒机 → 核心业务区（仅放行堡垒机IP）。
3. 开启防火墙日志发送至日志平台，每日检查“拒绝”TOP 10源IP。

### 五、合规检查清单

| 检查项 | 合规标准 | 检查命令/方法 |
|-------|---------|--------------|
| 区域隔离 | 核心区无公网IP | `curl ifconfig.me` 在核心区执行应超时 |
| SSH访问 | 仅管理区可连 | `nmap -p22 核心区IP` 从办公区应filtered |
| 密码策略 | ≥12位，90天 | `chage -l username` |
| 日志留存 | ≥180天 | `ls -l /var/log/audit/` 查看轮转配置 |
| 防火墙规则 | 无0.0.0.0/0放行22 | 云控制台安全组检查 |
| 堡垒机 | 所有运维经堡垒机 | 抽查直连记录，应无 |
| WAF | 开启拦截模式 | 发送 `?id=1' OR '1'='1` 应返回403 |
| 审计告警 | 登录失败5次告警 | 模拟失败登录，检查告警邮件 |

**每月合规巡检命令示例：**
```bash
# 检查异常登录
lastb | head -20
# 检查监听端口
netstat -tulnp | grep -E '22|3389|3306'
# 检查防火墙规则
iptables -L -n --line-numbers
```

未通过项需在5个工作日内整改，并记录于等保台账。
