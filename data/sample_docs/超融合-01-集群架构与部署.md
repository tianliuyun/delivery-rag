## 超融合集群架构与部署指南

## 1. 架构概述

超融合基础设施（HCI）将计算、存储、网络资源通过软件定义方式融合于标准 x86 服务器节点，形成统一资源池。典型架构包含三个核心组件：

- **分布式存储层**：基于 Ceph 或 vSAN 构建，数据以多副本或纠删码形式跨节点分布
- **虚拟化层**：KVM / ESXi / Hyper-V 运行于各节点
- **管理平面**：统一纳管集群、监控告警、生命周期运维

### 1.1 节点角色

| 角色 | 职责 | 最低配置建议 |
|------|------|-------------|
| 管理节点 | 承载 API、调度、监控、数据库 | 16C / 64GB / 2×480GB SSD RAID1 |
| 计算节点 | 运行虚拟机负载 | 32C / 256GB / 2×480GB SSD RAID1 |
| 存储节点 | 提供 OSD 存储容量 | 16C / 128GB / 12×4TB HDD + 2×1.6TB NVMe |
| 融合节点 | 同时承担计算+存储 | 32C / 256GB / 混合盘配置 |

> 生产环境建议至少 3 节点起步，管理节点独立部署（3 节点做高可用），计算与存储可融合部署。

## 2. 网络平面划分

推荐采用 4 平面物理隔离或 VLAN 隔离：

| 平面 | VLAN 示例 | 网段示例 | 用途 | 带宽要求 |
|------|-----------|----------|------|----------|
| 业务平面 | VLAN 100 | 10.10.100.0/24 | 虚拟机流量、南北向 | 10GE/25GE |
| 存储平面 | VLAN 200 | 10.10.200.0/24 | 副本同步、OSD 心跳 | 25GE 推荐 |
| 管理平面 | VLAN 300 | 10.10.300.0/24 | API、监控、BMC | 1GE |
| 带外管理 | VLAN 400 | 10.10.400.0/24 | IPMI/BMC | 1GE |

### 2.1 关键端口清单

| 服务 | 端口 | 协议 |
|------|------|------|
| Ceph Monitor | 3300, 6789 | TCP |
| Ceph OSD | 6800-7300 | TCP |
| Ceph RGW | 7480 | TCP |
| API Server | 8443 | TCP |
| etcd | 2379-2380 | TCP |
| 数据库 | 5432 | TCP |
| 监控 Prometheus | 9090 | TCP |
| BMC/IPMI | 623 | UDP |

### 2.2 网络配置示例（存储平面 Bond）

```bash
nmcli con add type bond con-name bond1 ifname bond1 mode 802.3ad
nmcli con add type ethernet con-name bond1-slave1 ifname ens1f0 master bond1
nmcli con add type ethernet con-name bond1-slave2 ifname ens1f1 master bond1
nmcli con mod bond1 ipv4.addresses 10.10.200.11/24 ipv4.method manual
nmcli con mod bond1 +ipv4.routes "10.10.200.0/24"
nmcli con up bond1
```

MTU 建议存储平面统一设置为 9000（Jumbo Frame），需交换机同步配置。

## 3. 部署前检查清单

1. **硬件检查**
   - 所有节点 CPU 型号、内存容量一致（避免异构导致调度倾斜）
   - 磁盘固件版本统一，NVMe 盘确认 `nvme list` 可识别
   - RAID 卡处于 JBOD/HBA 模式，禁止 RAID0 单盘
2. **固件与驱动**
   - BIOS 版本 ≥ 厂商推荐基线，开启 VT-x/AMD-V、IOMMU
   - 网卡固件更新至最新稳定版
3. **网络验证**
   - 各平面 `ping` 连通性、`iperf3` 带宽测试 ≥ 线速 90%
   - 交换机端口 MTU、LACP 配置核对
   - DNS 正反向解析、NTP 源可达（`chronyc sources`）
4. **系统基线**
   - OS 版本统一（如 CentOS 7.9 / Ubuntu 22.04）
   - 关闭 SELinux 或配置策略、关闭防火墙或放行上述端口
   - 时间同步偏差 < 100ms
   - `/etc/hosts` 包含所有节点主机名映射
5. **容量规划**
   - 原始容量预留 ≥ 30% 冗余
   - 副本策略默认 3 副本，可用容量 = 原始容量 / 3

## 4. 多节点集群初始化步骤

以下以 3 节点（node01/02/03）为例：

**步骤 1：准备首个管理节点**

```bash
# 安装部署工具
yum install -y hci-deployer ceph-deploy
# 初始化配置
hci-deployer init --cluster-name prod-hci --mgmt-ip 10.10.300.11
```

**步骤 2：生成集群 Token 并加入节点**

```bash
# node01 生成 token
hci-deployer token create --role compute,storage --ttl 24h
# 输出示例：eyJhbGciOi...（复制到 node02/03）
# node02/03 执行加入
hci-deployer join --token eyJhbGciOi... --mgmt-ip 10.10.300.11
```

**步骤 3：校验节点状态**

```bash
hci-deployer node list
# 期望输出 3 节点均为 Ready
ceph -s
# 期望 health: HEALTH_OK，mon 数量 3
```

**步骤 4：配置存储池与副本策略**

```bash
ceph osd pool create vol01 128 128
ceph osd pool set vol01 size 3
ceph osd pool set vol01 min_size 2
ceph osd pool application enable vol01 rbd
```

**步骤 5：网络平面绑定**

```bash
hci-deployer network set --plane storage --cidr 10.10.200.0/24 --mtu 9000
hci-deployer network set --plane business --cidr 10.10.100.0/24 --mtu 1500
```

**步骤 6：集群健康检查**

```bash
hci-deployer cluster verify --full
# 检查项：mon quorum、osd up/in、网络延迟、时钟偏差
```

**步骤 7：启用高可用与监控**

```bash
hci-deployer ha enable --vip 10.10.300.100
hci-deployer monitor enable --prometheus --grafana
```

## 5. 部署后验证

- 创建测试虚拟机并迁移，验证在线迁移 < 30s
- 模拟单节点断电，确认数据不丢失、集群 5 分钟内恢复 HEALTH_OK
- 检查 Grafana 面板：OSD 延迟 < 20ms，网络丢包率 0
- 输出交付报告，记录集群 ID、节点清单、网段、副本策略
