## 超融合存储集群运维指南

### 一、适用范围与前置说明

本指南适用于基于 Ceph 引擎的超融合存储集群（典型版本 Nautilus/Octopus/Quincy），覆盖存储池降级、副本不足、OSD 异常三类高频故障，以及副本策略与容量管理规范。默认集群已部署 `ceph-mon`（默认端口 **3300/6789**）、`ceph-mgr`（默认端口 **6800-7300**）、`ceph-osd`（默认端口 **6800-7300**）。

统一在管理节点执行命令，前置检查：

```bash
ceph -s
ceph osd tree
ceph df detail
```

---

### 二、存储池降级处理

#### 2.1 判定标准

`ceph -s` 输出中 `health` 为 `HEALTH_WARN` 或 `HEALTH_ERR`，且 `pgs` 行出现 `degraded`、`undersized`、`inactive` 等状态。

#### 2.2 处理步骤

1. 确认降级范围：
   ```bash
   ceph pg dump_stuck degraded
   ceph pg dump_stuck undersized
   ```
2. 定位异常 OSD：
   ```bash
   ceph osd tree | grep -v "up"
   ceph osd df | sort -k 8 -n
   ```
3. 若为单 OSD 短暂抖动，等待 **300 秒**（`mon_osd_report_timeout` 默认值）观察是否自愈。
4. 若 OSD 持续 `down`，执行：
   ```bash
   ceph osd out <osd-id>
   systemctl restart ceph-osd@<osd-id>
   ```
5. 恢复后重新加入：
   ```bash
   ceph osd in <osd-id>
   ```
6. 观察回填进度，控制回填速率避免业务抖动：
   ```bash
   ceph tell osd.* injectargs '--osd-max-backfills=1'
   ceph tell osd.* injectargs '--osd-recovery-max-active=2'
   ```

### 三、副本不足（undersized）处理

#### 3.1 常见原因

- OSD 离线导致 PG 副本数低于 `size`；
- CRUSH 规则变更后数据未完成重分布；
- 新建池未达到最小副本数。

#### 3.2 处理步骤

1. 查看具体 PG：
   ```bash
   ceph pg <pgid> query
   ```
2. 若因 OSD 离线，参考第二章恢复 OSD。
3. 若因 CRUSH 规则异常，检查规则：
   ```bash
   ceph osd crush rule dump <rule-name>
   ```
4. 强制触发恢复：
   ```bash
   ceph osd pool set <pool-name> pg_autoscale_mode off
   ceph pg repeer <pgid>
   ```
5. 验证恢复结果：
   ```bash
   ceph -s | grep -E "degraded|undersized"
   ```
   期望输出中 `degraded` 与 `undersized` 均为 **0**。

### 四、OSD 异常处理

#### 4.1 异常分类

| 状态 | 含义 | 处理优先级 |
|------|------|-----------|
| down | 进程不可用 | 高 |
| out | 已移出数据分布 | 高 |
| nearfull | 使用率 ≥ 85% | 中 |
| full | 使用率 ≥ 95% | 紧急 |

#### 4.2 处理流程

1. 查看 OSD 详情：
   ```bash
   ceph osd metadata <osd-id>
   journalctl -u ceph-osd@<osd-id> -n 200
   ```
2. 磁盘故障时更换磁盘并重建 OSD：
   ```bash
   ceph-volume lvm zap /dev/sdX --destroy
   ceph-volume lvm create --data /dev/sdX
   ```
3. 若为 `nearfull`，临时调整阈值：
   ```bash
   ceph osd set-nearfull-ratio 0.88
   ceph osd set-full-ratio 0.95
   ```
4. 恢复后取消临时阈值：
   ```bash
   ceph osd unset-nearfull-ratio
   ceph osd unset-full-ratio
   ```

### 五、副本策略配置

#### 5.1 策略规范

- 一般业务池：**至少 2 副本**；
- 重要数据池（数据库、核心业务）：**3 副本**；
- 禁止使用 `size=1` 用于生产池。

#### 5.2 配置命令

```bash
# 创建 2 副本池
ceph osd pool create pool-general 128 128
ceph osd pool set pool-general size 2
ceph osd pool set pool-general min_size 1

# 创建 3 副本池
ceph osd pool create pool-critical 128 128
ceph osd pool set pool-critical size 3
ceph osd pool set pool-critical min_size 2

# 启用应用模式
ceph osd pool application enable pool-general rbd
ceph osd pool application enable pool-critical rbd
```

#### 5.3 校验

```bash
ceph osd pool get pool-critical size
ceph osd pool get pool-critical min_size
```

### 六、容量预警与扩容建议

#### 6.1 阈值定义

| 级别 | 使用率 | 动作 |
|------|--------|------|
| 预警 | 70% | 通知容量规划 |
| 警告 | 80% | 启动扩容评估 |
| 严重 | 85% | 立即扩容 |
| 紧急 | 95% | 停止写入，紧急扩容 |

#### 6.2 监控命令

```bash
ceph df detail
ceph osd df tree
```

#### 6.3 扩容建议

1. 单节点新增磁盘不少于 **4 块**，保持故障域均衡。
2. 扩容后执行数据重平衡：
   ```bash
   ceph osd reweight-by-utilization 120
   ```
3. 扩容后 24 小时内持续观察：
   ```bash
   watch -n 30 'ceph -s; ceph df'
   ```
4. 若单池容量超过 **70%** 且集群整体超过 **75%**，建议优先横向扩容节点而非单节点加盘。

---

### 七、日常巡检清单

- 每日：`ceph -s`、`ceph osd tree`、`ceph df detail`；
- 每周：检查 `nearfull` OSD、PG 分布均衡度；
- 每月：核对副本策略与业务等级匹配情况；
- 每季度：演练一次 OSD 故障恢复流程。
