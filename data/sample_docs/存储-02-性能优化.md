## 分布式存储性能优化指南

### 一、SSD缓存层配置

SSD缓存层用于加速元数据及热点数据读写，建议采用NVMe SSD，容量不低于总数据量的10%。

**配置步骤（以Ceph + BlueStore为例）：**

1. 创建DB/WAL设备：
```bash
ceph-volume lvm create --bluestore --data /dev/sdb --block.db /dev/nvme0n1p1 --block.wal /dev/nvme0n1p2
```
2. 设置缓存池：
```bash
ceph osd pool create ssd-cache 128 128
ceph osd tier add data-pool ssd-cache
ceph osd tier cache-mode ssd-cache writeback
ceph osd tier set-overlay data-pool ssd-cache
```
3. 关键参数阈值：
- `cache_target_dirty_ratio`：0.4
- `cache_target_full_ratio`：0.8
- `cache_min_flush_age`：600（秒）
- `cache_min_evict_age`：1800（秒）

监控端口：Ceph Dashboard 8443，Prometheus 9090。

### 二、智能分层策略

按访问频率将数据分为热、温、冷三层，自动迁移。

**策略定义：**
- 热层：SSD/NVMe，访问频率 > 10次/小时
- 温层：SAS/HDD，访问频率 1~10次/小时
- 冷层：大容量HDD/对象存储，访问频率 < 1次/天

**迁移命令示例（Ceph）：**
```bash
ceph osd pool set data-pool hit_set_type bloom
ceph osd pool set data-pool hit_set_count 4
ceph osd pool set data-pool hit_set_period 3600
ceph osd pool set data-pool target_max_bytes 10995116277760
```
建议每15分钟执行一次分层评估，迁移窗口设为业务低峰期（如02:00-05:00）。

### 三、条带大小选择

条带大小影响吞吐与IOPS，需匹配业务IO模型。

| 业务类型 | 推荐条带 | 说明 |
|--------|--------|------|
| 大文件顺序读 | 1M~4M | 提升吞吐 |
| 数据库OLTP | 64K~128K | 降低延迟 |
| 小文件/元数据 | 16K~32K | 提高IOPS |
| 视频流 | 4M~8M | 减少寻道 |

**设置命令（Lustre）：**
```bash
lfs setstripe -c 8 -S 4M /mnt/lustre/data
```
**Ceph RBD：**
```bash
rbd create --size 102400 --stripe-unit 65536 --stripe-count 8 data-img
```

### 四、小文件合并

小文件（<64KB）直接存储会导致元数据膨胀。建议合并为大于1MB的包。

**操作步骤：**
1. 启用合并工具（如Hadoop HAR或自研打包）：
```bash
hadoop archive -archiveName data.har -p /source /dest
```
2. 设置合并阈值：
- `dfs.namenode.fs-limits.min-block-size=1048576`
- 合并后单文件目标大小：64MB~128MB
3. 对已合并文件建立索引，保留原路径映射，应用层透明访问。

### 五、热点数据识别

通过采样与统计识别热点，指导缓存与分层。

**方法：**
- 使用`ceph osd pool stats`或`iostat -x 1`观察IO分布。
- 部署OpenTelemetry采集访问日志，按对象/块统计QPS。
- 阈值：单对象QPS > 100或带宽 > 10MB/s即标记为热点。

**自动识别脚本示例：**
```bash
for obj in $(rados ls -p data-pool); do
  qps=$(rados -p data-pool get obj /dev/null | wc -l)
  if [ $qps -gt 100 ]; then echo "$obj" >> hot.list; fi
done
```
将`hot.list`导入缓存层预热：
```bash
rados -p ssd-cache cache-flush-evict-all
```

### 六、性能基线测试方法

**测试工具：**
- FIO 3.35+：块层与文件层
- COSBench：对象存储
- IOR：并行文件系统

**基线测试步骤：**
1. 清空缓存：`echo 3 > /proc/sys/vm/drop_caches`
2. 顺序读测试（1M块，4并发）：
```bash
fio --name=seqread --rw=read --bs=1M --numjobs=4 --size=10G --runtime=120 --time_based --group_reporting
```
3. 随机写测试（4K，32队列深度）：
```bash
fio --name=randwrite --rw=randwrite --bs=4k --iodepth=32 --numjobs=8 --size=5G --runtime=120 --time_based
```
4. 记录基线指标：
- 顺序读带宽 ≥ 2GB/s（NVMe）
- 随机写IOPS ≥ 200K
- 平均延迟 < 1ms
5. 每季度复测，偏差超过15%需排查。
