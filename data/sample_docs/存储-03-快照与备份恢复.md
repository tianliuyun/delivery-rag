## 存储快照与备份恢复操作指南

### 1. 适用范围与前置条件

本指南适用于基于 Ceph RBD、华为 OceanStor 或同类块存储的云平台交付场景。执行前确认：
- 存储集群健康状态为 `HEALTH_OK`（Ceph）或 `Normal`（OceanStor）。
- 管理节点已安装 `rbd`、`ceph-common`、`snapctl` 或厂商 CLI。
- 备份服务器与存储管理口互通，默认端口：SSH 22、Ceph Monitor 6789、RADOS 6800-7300、OceanStor CLI 8088。

### 2. 快照创建与保留策略

#### 2.1 创建快照

Ceph RBD 示例（卷名 `vol-prod-01`，池 `rbd`）：

```bash
rbd snap create rbd/vol-prod-01@snap-$(date +%Y%m%d%H%M)
```

OceanStor CLI 示例：

```bash
snapctl create --name snap_$(date +%Y%m%d%H%M) --lun vol-prod-01
```

#### 2.2 保留策略

| 快照类型 | 保留周期 | 最大数量 | 触发方式 |
|----------|----------|----------|----------|
| 小时级 | 24 小时 | 24 | 每小时整点 |
| 日级 | 14 天 | 14 | 每日 02:00 |
| 周级 | 8 周 | 8 | 每周日 03:00 |
| 月级 | 6 个月 | 6 | 每月 1 日 04:00 |

超过保留数量时，按时间最早优先删除：

```bash
rbd snap purge rbd/vol-prod-01 --keep 14
```

阈值告警：快照占用超过卷容量 20% 时触发工单；超过 30% 自动暂停新快照创建。

### 3. 备份任务配置

#### 3.1 全量备份

使用 `rbd export` 或厂商备份工具，输出至备份存储：

```bash
rbd export rbd/vol-prod-01@snap-202501010200 /backup/vol-prod-01-full-20250101.img
```

备份窗口：每日 01:00-05:00，并发任务不超过 4 个，单任务带宽限制 200 MB/s。

#### 3.2 增量备份

基于上次快照差异导出：

```bash
rbd export-diff rbd/vol-prod-01@snap-202501010200 rbd/vol-prod-01@snap-202501020200 /backup/vol-prod-01-inc-20250102.diff
```

#### 3.3 任务调度

在备份服务器 `crontab` 中配置：

```bash
0 1 * * * /opt/backup/run_full_backup.sh >> /var/log/backup/full.log 2>&1
0 2 * * * /opt/backup/run_inc_backup.sh >> /var/log/backup/inc.log 2>&1
```

校验：每次备份完成后执行 `md5sum` 比对，失败重试 3 次，间隔 10 分钟。

### 4. 数据恢复演练步骤

1. **隔离环境准备**：在测试租户下创建临时卷 `vol-restore-test`，容量不低于源卷。
2. **停止写入**：对源卷执行 `rbd snap create` 生成一致性快照，或卸载文件系统。
3. **导入备份**：
   ```bash
   rbd import /backup/vol-prod-01-full-20250101.img rbd/vol-restore-test
   ```
4. **应用增量**：
   ```bash
   rbd import-diff /backup/vol-prod-01-inc-20250102.diff rbd/vol-restore-test
   ```
5. **挂载验证**：映射为块设备并挂载：
   ```bash
   rbd map rbd/vol-restore-test
   mount /dev/rbd0 /mnt/restore
   ```
6. **数据比对**：使用 `diff -r` 或 `rsync -avn` 对比关键目录，记录差异文件数。
7. **业务验证**：启动测试实例，执行核心事务脚本，确认无报错。
8. **清理**：卸载、取消映射、删除临时卷。

### 5. 恢复一致性检查清单

- [ ] 快照时间点与业务低峰期一致，无未落盘数据。
- [ ] 备份文件 MD5 与源端一致，无截断。
- [ ] 恢复后卷容量、扇区大小与原卷一致。
- [ ] 文件系统 `fsck` 无错误（ext4/xfs）。
- [ ] 数据库 `CHECK TABLE` 或 `pg_checksums` 通过。
- [ ] 应用日志无 `I/O error`、`corruption` 关键字。
- [ ] 恢复 RTO ≤ 30 分钟，RPO ≤ 15 分钟。
- [ ] 演练记录归档至 `/var/log/dr/drill-YYYYMMDD.log`。

未通过项须在 24 小时内修复并重新演练。
